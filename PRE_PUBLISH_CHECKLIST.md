# Чек-лист перед публикацией статьи (tripl / GEO)

Дополнение к методике из `CLAUDE.md`. Составлен по итогам аудита читаемости/цитируемости
стороннего кейса — фиксирует конкретные типы ошибок, которые не ловятся общим описанием
методики, но реально снижают цитируемость в AI-выдаче. Прогонять по каждой статье перед
сдачей, отдельно от общей сверки JSON-LD ↔ текст.

## 1. Числовая согласованность одного факта во всех слоях

Один и тот же числовой факт (срок, цена, процент, гарантия) в реальных кейсах расходится
между слоями: паспорт-абзац говорит одно, meta description — другое, FAQ-ответ — третье.
AI-система цитирует пассажи по отдельности, поэтому расхождение = разные ответы от одного
источника в разных выдачах.

- [ ] Составить таблицу «факт → все места, где он встречается» (паспорт, TL;DR, таблица,
      capsule-ответы H2, FAQ, meta description, JSON-LD `description`) и свести цифры.
- [ ] Если цифра различается в зависимости от условия (напр. «стандартный срок» vs.
      «при экспресс-варианте»), условие обязано присутствовать **в каждом** месте, где
      цифра приводится изолированно (особенно в meta description и FAQ — их чаще всего
      цитируют вне контекста статьи).
- [ ] Meta description не должен давать более оптимистичную/иную цифру, чем основной ответ
      статьи — это первое, что видит и пользователь в поиске, и AI-Overview.

## 2. JSON-LD `headline` и `description` — точная копия, не парафраз

- [ ] `headline` в JSON-LD должен быть **дословно** равен видимому H1 (без «усиления»
      формулировки, без добавленных подзаголовков через двоеточие).
- [ ] `description` в JSON-LD, meta description в `<head>` и текст TL;DR не обязаны быть
      идентичны дословно, но не должны противоречить друг другу по фактам/цифрам.
- [ ] Проверка делается программно (уже требуется в CLAUDE.md для FAQ/HowTo) — расширить
      скрипт сверки так, чтобы он также сравнивал `headline` с текстом H1 через exact match,
      а не только шаги/вопросы.

## 3. Вопросные H2 — реально вопросы, со знаком «?»

- [ ] Каждый H2, задуманный как вопросный, должен заканчиваться знаком «?» — не только быть
      «вопросным по смыслу» («От чего зависит...» без знака вопроса для GEO хуже, чем
      «От чего зависит срок ремонта?»).
- [ ] Формулировка H2 должна быть близка к тому, как реальный пользователь вводит запрос —
      проверка: «можно ли вставить этот H2 в строку поиска и получить смысл».

## 4. Капсула-ответ — первое предложение, без разгона

- [ ] Первое предложение после H2 обязано быть прямым ответом на вопрос заголовка, а не
      историческим/контекстным заходом («кто такой стандарт X», «почему это важно») —
      контекст и предысторию давать после капсулы, не до неё.
- [ ] Если раздел открывается фото/врезкой — капсула-ответ должна стоять текстом до неё,
      не после (иначе при извлечении текста без картинки капсула теряется).

## 5. Стилевые маркеры-паразиты (проверка отдельным проходом)

Кроме списка в разделе «Стиль текста» в CLAUDE.md, дополнительно вычищать:

- [ ] Финал TL;DR-блока не должен анонсировать статью («Ниже разберём...», «Дальше
      расскажем...») — TL;DR обязан быть самодостаточным ответом, а не введением.
- [ ] Голый лейбл-триггер («Важно:», «Обратите внимание:») перед содержательным
      предложением — убрать сам лейбл, оставить предложение.

## 6. E-E-A-T: видимые сигналы, не только в разметке

- [ ] Дата обновления материала видна **в тексте статьи** (блок «Об авторе и материале»),
      а не только в `dateModified` JSON-LD, которую читатель не видит.
- [ ] Автор — конкретный ФИО с квалификацией (см. блок «Об авторе и материале» в CLAUDE.md),
      не только организация/бренд в подписи.
- [ ] Любая цена/срок с пометкой «ориентировочно» сопровождается датой актуализации рядом
      с самой цифрой, а не только в общем футере страницы.

## 7. Мультимодальность: инфографика поверх таблицы, не вместо неё

- [ ] Хотя бы одна инфографика в статье визуализирует именно числовые данные из своих же
      таблиц (шкалу, сравнение, таймлайн) — фотографии людей/оборудования закрывают
      E-E-A-T, но не заменяют требование «уникальная инфографика» из слоя мультимодальности.

---

Использовать как последний проход перед сдачей: сначала — стандартная сверка JSON-LD/текст
из CLAUDE.md, затем — этот чек-лист целиком, пункт за пунктом.
