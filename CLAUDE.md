# Medford — производство контента

Проект: статьи + инфографика + JSON-LD для medford.ru (сервис ремонта УЗИ-оборудования).
Все материалы делаются по методике **tripl** (семантические триплеты для ранжирования и
цитирования в AI-выдаче) — см. полный скилл в чате-источнике; здесь — рабочая выжимка.

## Методика tripl (кратко)

- Триплет = субъект → предикат → объект. Каждый значимый факт внедряется **трижды**: текст +
  Schema.org + внешний источник. Триплет в одном слое — слабый.
- Контент должен проходить 5 слоёв воронки: лексика (сущность в title/H1) → семантика (одна
  страница = одна сущность, без расфокуса) → сущности (граф, sameAs) → пассажи (TL;DR,
  самодостаточные ответы на вопросные H2, HTML-таблицы) → мультимодальность (уникальные
  инфографики, осмысленный alt).
- Структура статьи: паспорт-абзац под H1 (4–6 триплетов с числами) → TL;DR (короткий, 70–90
  слов, извлекаемый ответ — не растягивать перечислением деталей каждого шага) → разделы
  с вопросными H2, каждый открывается капсулой-ответом (40–70 слов) → таблицы дублируются
  HTML `<table>`, не только картинкой → FAQ → источники → «Об авторе и материале».
- Факты не выдумываются. Частота у конкурентов задаёт приоритет: есть у 8+/10 = обязательно
  внедрить; 0/10 при наличии у нас = точка отстройки, годный цитируемый пассаж.
- Явно разделять: подтверждено (с источником) / требует оговорки (указать источник и
  ограничение) / писать нельзя (нет данных — не сочинять число или статус).

## GEO — обязательное требование для каждой статьи

Статья пишется в первую очередь под цитирование в AI-выдаче (AI Overviews, Нейро, ChatGPT,
Perplexity, Claude) — GEO приоритетнее классического SEO, но не заменяет его.

- Обратная пирамида: извлекаемый ответ в первых ~150 словах (TL;DR) сразу после паспорт-абзаца
  под H1 — не в конце статьи.
- Одна страница = одна сущность: расфокус и каннибализация между статьями серии запрещены,
  смежные темы — отдельный URL с перелинковкой в обе стороны.
- Каждый вопросный H2 открывается самодостаточной капсулой-ответом (40–70 слов), которая
  цитируема отдельно от остального текста, без обрыва картинкой посередине.
- Терминология точная и однозначная (ZIF, front-end ASIC, probe-select, EEPROM/ID-чип и т.п.);
  рекламные штампы («лучший», «№1», «профессиональный подход») вычищать — их отфильтровывают
  генеративные системы.
- Таблицы дублируются HTML/нативной таблицей, не только картинкой.
- E-E-A-T: автор с квалификацией, дата обновления (ревизия не реже раза в 3–6 месяцев), блок
  «Источники» со ссылкой на конкретные даташиты/мануалы/стандарты.
- JSON-LD синхронен с видимым текстом дословно — это тоже требование GEO, а не только
  Schema.org для классического SEO.
- Техническая доступность (для веб-версии, не для docx): серверный рендер, robots.txt не
  блокирует AI-краулеров (GPTBot, ChatGPT-User, PerplexityBot, ClaudeBot, Google-Extended,
  YandexBot), желателен `llms.txt`.

## Формат вывода

**Статья** — `.docx` (python-docx): Title + Heading 1/2, TL;DR первым разделом сразу под
заголовком, ровно N шагов если заголовок/H1 обещает число, HTML-таблица для табличных данных,
FAQ, источники, блок «Об авторе и материале» с фактами компании (см. выше).

**Инфографика** — JPG: 2× supersampling + LANCZOS downscale, quality=94, subsampling=0, шрифт
DejaVu Sans (кириллица без артефактов). Палитра: тёмно-синий `#102C4C`, стальной синий
`#2C5F8A`, бирюзовый `#0E8C8C`, зелёный `#2E9E5B` (годен/дальше), красный `#C83E3E` (отказ),
янтарный `#D69614` (внимание), приглушённый текст `#607080`. Заголовочный бэнд (тёмно-синий +
бирюзовое подчёркивание) вверху, подпись «Рис. N. …» курсивом под изображением. Если табличные
данные уже даны HTML/нативной таблицей в статье — не дублировать их отдельной инфографикой;
инфографика нужна там, где несёт то, чего нет в тексте дословно (схемы, деревья решений,
матрицы, определители), а не там, где просто перерисовывает таблицу.

**JSON-LD** — отдельный `.html` со скриптами `application/ld+json`: `TechArticle` + `HowTo`
(если в статье есть пронумерованные шаги, ровно столько же `step[]`) + `FAQPage` (все вопросы
статьи) + `Organization`. Разметка должна дословно совпадать с видимым текстом — сверять
программно (парсить JSON, искать точное вхождение строк в параграфы docx) перед сдачей.
`sameAs` на Wikidata для брендов: GE Q1152374, Siemens Q472451, Philips Q2087959,
Mindray Q15138136, Samsung Medison Q6715307, Canon Medical Q6149487.

**Плейсхолдеры** для неизвестных данных — `[ФИО]`, `[N лет]`, `[ссылка]`, `[телефон]`, `[URL]` и
т.п. Не выдумывать вместо них.

## Стиль текста (без ИИ-паттернов)

- Тире для нулевой связки («X — это Y») и парентетичных вставок — грамматическая норма русского
  языка, не признак ИИ-генерации. Механически не вычищать (в отличие от английского текста, где
  overuse тире — реальный tell).
- Убирать: анонсы-пустышки («Разберём...», «Важно понимать:», «Стоит подчеркнуть»); жирный
  ярлык + точка как отдельный пункт списка («Термин. Пояснение.» → «Термин: пояснение» без
  жирного, или цельное предложение); саморефлексивные фразы («Это ключевая мысль статьи»);
  заголовок с последующей пустой фразой-разгоном перед реальным содержанием.
- Оставлять: перечисления через тире/точку с запятой; топик-предложения с реальным
  содержанием; повторяющиеся связки вроде «Логика проста», если они несут смысл, а не
  вставлены механически.
